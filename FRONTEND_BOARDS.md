# Инструкция для фронта: Доска

Документ доски хранит сервер. Доска не привязана к занятию и расписанию. Её создаёт учитель: даёт название и выбирает учеников или одну группу. Холст один. Его видят и правят учитель и те, кому доска назначена.

Правки идут как в Miro: пока доска открыта, клиент держит одно WebSocket-соединение. Документ целиком приходит один раз при подключении, дальше по сети ходят только маленькие операции по объектам: добавить, сдвинуть, дописать точки штриха, удалить. Есть живые курсоры. `PUT` документа и поток `events` больше не существуют.

Базовый URL — тот же, что у остального API. Авторизация HTTP — `Authorization: Bearer <token>`, у WebSocket — `?token=<token>` в адресе.

Поля доски в JSON — camelCase (`teacherId`, `groupId`, `studentIds`, `createdAt`).

---

## Документ

`GET` одной доски, создание доски и `board` в сообщении `snapshot` — одно и то же:

```json
{
  "id": "6f1c2a40-7b1e-4d2a-9c33-0a1b2c3d4e5f",
  "title": "Дроби",
  "teacherId": 7,
  "groupId": null,
  "studentIds": [45, 46],
  "revision": 1,
  "createdAt": "2026-09-28T00:13:00.000Z",
  "updatedAt": "2026-09-28T00:13:00.000Z",
  "camera": { "x": 0, "y": 0, "zoom": 1 },
  "objects": []
}
```

Если доска на группу, `groupId` — id группы, `studentIds` — пустой массив. Состав берётся из группы: ученик, которого добавили позже, увидит доску сам. Если доска на конкретных учеников, `groupId` равен `null`, а `studentIds` — их id.

`id` доски — UUID-строка. `teacherId`, `groupId` и элементы `studentIds` — числа.

`revision` — номер снимка в базе. Сервер увеличивает его, когда пишет открытую доску в базу. Клиенту он не нужен: порядок правок задаёт `seq` в WebSocket.

`camera` — стартовый вид доски: сдвиг и масштаб мира. Координаты объектов — пиксели мира, не экрана.

Порядок в `objects` — порядок отрисовки: первый снизу, последний сверху.

Пока доска открыта у кого-то, `GET` отдаёт её живое состояние из памяти сервера, а не снимок из базы.

Список досок приходит без `objects`:

```json
{
  "id": "6f1c2a40-7b1e-4d2a-9c33-0a1b2c3d4e5f",
  "title": "Дроби",
  "teacherId": 7,
  "groupId": null,
  "studentIds": [45, 46],
  "updatedAt": "2026-09-28T00:40:12.000Z",
  "objectCount": 4
}
```

## Объекты

Каждый элемент `objects` одной формы. Неизвестные ключи в `props` сервер сохраняет.

```json
{
  "id": "b7e1c2d0-1111-4222-8333-444455556666",
  "type": "sticky",
  "x": 120,
  "y": 80,
  "w": 200,
  "h": 160,
  "rotation": 0,
  "props": {}
}
```

`id` объекта — непустая строка. Координаты, размеры и `rotation` — конечные числа.

| `type` | Что лежит в `props` |
| --- | --- |
| `sticky` | `text`, `color` (`#fde68a` и другие), `fontSize` |
| `text` | `text`, `fontSize` |
| `shape` | `shape`: `rect` или `ellipse`, `fill`, `stroke` |
| `arrow` | `x1`, `y1`, `x2`, `y2` относительно рамки, `color`, `width` |
| `draw` | `points`: `[{ "x", "y" }]`, `color`, `width` |
| `image` | `fileId`, `src`, `name` |
| `geogebra` | `appName`: `geometry` или `graphing`, `ggbBase64`, `templateId` |

Лимит: до 200 объектов и до 8 МБ на документ. Операцию сверх лимита сервер отклоняет сообщением `error`.

## Живая доска (WebSocket)

Пока холст открыт — одно соединение. Через него и правки, и чужие изменения, и курсоры. Сохранять отдельно не нужно: сервер держит открытую доску в памяти и сам пишет её в базу раз в ~2 секунды и когда уходит последний участник.

```
wss://<api>/student/boards/{id}/ws?token=<token>
wss://<api>/teacher/boards/{id}/ws?token=<token>
```

Браузерный `WebSocket` не умеет заголовок `Authorization`, поэтому токен — в адресе. Все сообщения — JSON-текст.

### Отказ в доступе

Сервер принимает соединение и сразу закрывает его с кодом:

| Код | Значит |
| --- | --- |
| `4401` | нет токена или он неверный |
| `4403` | чужая доска или не та роль |
| `4404` | доски нет или её удалили |
| `4408` | клиент не успевал читать сообщения; переподключиться |

На `4401`, `4403` и `4404` переподключаться не нужно. На остальные коды и обрыв сети — переподключиться с паузой (1 с, 2 с, 4 с, до 30 с).

### Первое сообщение

```json
{
  "type": "snapshot",
  "seq": 0,
  "clientId": "a1b2c3d4e5f6",
  "board": { "id": "…", "title": "Дроби", "camera": {…}, "objects": [ … ], "…": "как в GET" },
  "peers": [{ "clientId": "f6e5d4c3b2a1", "userId": 7, "name": "Иван Петров", "role": "teacher" }]
}
```

`board` — документ целиком, нарисовать его вместо локального. `clientId` — id этого подключения. `peers` — кто ещё сейчас на доске. Это единственный раз, когда документ приходит целиком.

### Клиент → сервер

У каждой правки есть `opId` — строка, которую клиент придумывает сам, чтобы узнать ответ на неё.

| `type` | Поля | Что делает |
| --- | --- | --- |
| `upsert` | `object` — объект целиком | добавить или заменить объект. Новый ложится наверх |
| `patch` | `id`, `set` | изменить поля объекта. В `set` — любые из `x`, `y`, `w`, `h`, `rotation` и `props`. `props` сливается с текущими по ключам верхнего уровня |
| `append_points` | `id`, `points: [{x, y}]` | дописать точки к штриху `draw`, не пересылая весь штрих. До 10 000 точек за раз |
| `delete` | `ids: [...]` | удалить объекты. Неизвестные id пропускаются |
| `reorder` | `ids: [...]` | новый порядок отрисовки. Нужно перечислить все объекты доски ровно по разу |
| `title` | `title` | переименовать доску |
| `camera` | `camera: {x, y, zoom}` | запомнить стартовый вид. Другим участникам не рассылается |
| `cursor` | `x`, `y` | положение курсора в координатах мира. Без `opId`, без ответа, нигде не хранится |
| `sync` | — | попросить новый `snapshot` |

```json
{ "type": "patch", "opId": "k7", "id": "b7e1c2d0-…", "set": { "x": 140, "y": 95 } }
```

Пока объект тащат, `patch` слать не чаще раза в 50 мс. Штрих: в начале `upsert` с первыми точками, потом `append_points` пачками раз в 50 мс. Курсор — не чаще раза в 50 мс.

### Сервер → клиент

**`ack`** — правка принята: `{ "type": "ack", "opId": "k7", "seq": 12 }`. Если сервер дописал в объект что-то своё (сейчас это `src` у картинки), в `ack` есть `object` — объект целиком, подставить его.

**`error`** — правка отклонена: `{ "type": "error", "opId": "k7", "detail": "Нет объекта b7e1…" }`. Чаще всего объект уже удалил кто-то другой. Откатить свою правку или отправить `sync` и перерисовать из `snapshot`.

**`op`** — правка другого участника:

```json
{ "type": "op", "seq": 13, "clientId": "f6e5d4c3b2a1", "op": { "type": "patch", "id": "…", "set": { "x": 140 } } }
```

`op` — та же операция, что клиент отправляет сам, без `opId`. Применить к локальной копии. Свои правки обратно не приходят: их клиент уже применил сам.

**`join`** / **`leave`** — участник подключился (`peer`) или ушёл (`clientId`). Убрать его курсор.

**`cursor`** — `{ "type": "cursor", "clientId": "…", "x": 10, "y": 20 }`.

**`deleted`** — учитель удалил доску. Следом соединение закрывается с кодом `4404`.

`seq` растёт на каждой принятой правке и общий для всех участников. По нему видно порядок.

### Обрыв

После переподключения придёт новый `snapshot`. Правки, на которые не пришёл `ack`, после `snapshot` отправить заново: `upsert`, `patch`, `delete` и `reorder` можно повторять безопасно. `append_points` повторять только если `ack` на него точно не пришёл.

```javascript
const ws = new WebSocket(`${WS_API}/student/boards/${id}/ws?token=${token}`);
const pending = new Map();
let n = 0;

function send(op) {
  const opId = String(++n);
  pending.set(opId, op);
  apply(op);
  ws.send(JSON.stringify({ ...op, opId }));
}

ws.onmessage = (event) => {
  const msg = JSON.parse(event.data);
  if (msg.type === "snapshot") {
    replaceBoard(msg.board);
    for (const [opId, op] of pending) {
      apply(op);
      ws.send(JSON.stringify({ ...op, opId }));
    }
  }
  if (msg.type === "ack") {
    pending.delete(msg.opId);
    if (msg.object) replaceObject(msg.object);
  }
  if (msg.type === "error") {
    pending.delete(msg.opId);
    ws.send(JSON.stringify({ type: "sync" }));
  }
  if (msg.type === "op") apply(msg.op);
  if (msg.type === "cursor") moveCursor(msg.clientId, msg.x, msg.y);
  if (msg.type === "leave") removeCursor(msg.clientId);
  if (msg.type === "deleted") closeBoard();
};
```

## Учитель

Роль `teacher` или `admin`. Ученик доску не создаёт.

### Создать

```
POST /teacher/boards
Content-Type: application/json
```

Либо ученики, либо одна группа. Оба поля вместе или ни одного — `400`, «Нужны ученики или группа, что-то одно».

```json
{ "title": "Дроби", "studentIds": [45, 46] }
```

```json
{ "title": "Групповая доска", "groupId": 3 }
```

Ученики должны быть привязаны к этому учителю, иначе `400`. Чужая группа — `404`. Пустое название — `400`.

**Ответ 200:** полный пустой документ, `revision` равен `1`.

### Список, открытие, правки, удаление

```
GET    /teacher/boards
GET    /teacher/boards/{id}
WS     /teacher/boards/{id}/ws?token=<token>
DELETE /teacher/boards/{id}
```

`GET /teacher/boards` — доски этого учителя, без `objects`, свежие сверху. `objectCount` и `updatedAt` в списке отстают от открытой доски на пару секунд.

`DELETE` удаляет доску и её картинки. Все, у кого доска открыта, получают `deleted`.

**Ответ 200:** `{ "ok": true }`.

Чужая доска — `403`. Неизвестный UUID — `404`.

## Ученик

Роль в токене — `student`.

```
GET /student/boards
GET /student/boards/{id}
WS  /student/boards/{id}/ws?token=<token>
```

В списке доски, где ученик указан в `studentIds`, и доски групп, в которых он сейчас состоит. Без `objects`, свежие сверху. Общей кнопки «новая доска» нет.

Ученик правит тот же документ, что и учитель, в той же комнате.

## Картинки

Файл в JSON доски не класть: ни base64, ни `data:`. Сначала загрузка, потом `fileId` в объекте.

```
POST /student/boards/images
POST /teacher/boards/images
Content-Type: multipart/form-data
```

Поле файла — `file`. Форматы: jpeg, png, webp. До 10 МБ. Тип определяется по содержимому.

**Ответ 200:**

```json
{
  "fileId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "name": "чертёж.png",
  "src": "https://…/boards/a1b2c3d4-e5f6-7890-abcd-ef1234567890.png"
}
```

`src` — публичный адрес, как у картинок заданий. `<img>` открывает его без `Authorization`.

На `upsert` картинки или `patch` с новым `fileId` сервер сам пишет `src` и возвращает объект в `ack`. Если такого файла нет или он с другой доски, `src` — пустая строка.

Удаление объекта с холста файл не стирает. Файл уходит, когда учитель удаляет доску, на которую картинку уже поставили.

## Шаблоны GeoGebra

Четыре id на клиенте (`right-triangle`, `circle`, `coordinates`, `parabola`) сервер сам не создаёт. Файл шаблона в документ доски не копируется: объект хранит `templateId`, а `ggbBase64` клиент берёт из `GET /board/geogebra-templates/{id}` и держит у себя. Если состояние апплета нужно сохранить на доске, клиент сам кладёт его в `props.ggbBase64` через `patch`.

`ggbBase64` — файл `.ggb` в base64, параметр `ggbBase64` у `GGBApplet`.

Пустая геометрия и пустые графики — не шаблоны. У них `templateId` равен `""`.

### Список и один шаблон

```
GET /board/geogebra-templates
GET /board/geogebra-templates/{id}?lessonId=123
```

Токен ученика или учителя. Список без base64, у каждого элемента есть `teacherId`.

`lessonId` необязателен и к доске не относится: это только способ взять шаблон учителя конкретного занятия. Без него ученик получает любой совпавший шаблон своих учителей, с меньшим `teacherId`. Учитель без `lessonId` получает свой.

Сервер сохраняет `props` как прислал клиент и не подставляет файл шаблона. Содержимое берётся отдельным `GET /board/geogebra-templates/{id}`.

### Учитель заводит шаблон

```
POST /teacher/geogebra-templates
Content-Type: multipart/form-data
```

| Поле | |
| --- | --- |
| `file` | файл `.ggb`, до 8 МБ |
| `id` | латиница, цифры, дефис и `_`, до 64 символов |
| `title` | до 255 символов |
| `appName` | `geometry` или `graphing` |

Такой `id` у этого учителя уже есть — `409`.

```
PUT    /teacher/geogebra-templates/{id}
DELETE /teacher/geogebra-templates/{id}
```

`PUT` принимает любое из полей `title`, `appName`, `file`. `DELETE` отвечает `{ "ok": true }`.

## Сценарий

1. Учитель жмёт «новая доска», вводит название и выбирает учеников или группу: `POST /teacher/boards`.
2. Ученик видит её в `GET /student/boards` и открывает WebSocket `/student/boards/{id}/ws`. Доска рисуется из `snapshot`.
3. Каждое действие сразу применяется на экране и уходит одной операцией: `upsert`, `patch`, `append_points`, `delete`. Таймера сохранения нет.
4. Второй участник получает `op` и применяет её к своей копии. Документ заново никто не качает.
5. При обрыве — переподключение, новый `snapshot`, повтор правок без `ack`.
6. Картинку сначала `POST .../boards/images`, потом `upsert` объекта с `fileId`. `src` придёт в `ack`.
7. Шаблон: `GET /board/geogebra-templates/{id}` и base64 в апплет на клиенте. В объект доски кладётся `templateId`.
