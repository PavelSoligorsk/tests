# Инструкция для фронта: Доска занятия

Документ доски хранит сервер. IndexedDB — мгновенный черновик в браузере: линия не ждёт сеть, на сервер уходит уже собранный JSON.

Живых курсоров нет. Один `PUT` заменяет документ целиком. Второй участник видит картину, когда сам снова делает `GET`.

Базовый URL — тот же, что у остального API. Авторизация — `Authorization: Bearer <token>`.

Поля доски в JSON — camelCase (`lessonId`, `ownerId`, `createdAt`). Это не как у уроков, там `student_id`.

---

## Как устроено занятие

У занятия из `POST /teacher/lessons` две доски, обе с одним `lessonId`:

| `kind` | Кто | Что это |
| --- | --- | --- |
| `class` | общее | Доска занятия. Пишет учитель. Ученик только читает. `ownerId` всегда `null`. |
| `student` | один ученик | Тетрадь этого ученика на это занятие. Пишет ученик. Учитель только читает. |
| `draft` | ученик | Личный холст без календаря. `lessonId` всегда `null`. Создаёт и удаляет только ученик. |

Индивидуальное занятие: одна `class` и одна `student` с `ownerId` этого ученика.

Групповое: одна `class` и по одной `student` на каждого ученика группы. Ученик, которого добавили в группу позже, получает тетрадь при следующем открытии.

Строки появляются при первом открытии доски, не в момент `POST /teacher/lessons`. Повторное открытие те же `id` не дублирует.

Удаление занятия удаляет его `class` и тетради и стирает их картинки. Черновики остаются.

## Документ

`GET` одной доски и успешный `PUT` возвращают одно и то же:

```json
{
  "id": "6f1c2a40-7b1e-4d2a-9c33-0a1b2c3d4e5f",
  "title": "Урок дробей",
  "lessonId": 123,
  "kind": "student",
  "ownerId": 45,
  "revision": 7,
  "createdAt": "2026-09-28T00:13:00.000Z",
  "updatedAt": "2026-09-28T00:40:12.000Z",
  "camera": { "x": 64, "y": 72, "zoom": 1 },
  "objects": []
}
```

Пустая доска: `revision` равен `1`, `camera` равен `{ "x": 0, "y": 0, "zoom": 1 }`, `objects` равен `[]`.

`id` доски — UUID-строка. `lessonId` и `ownerId` — числа, как у пользователей и уроков. У `class` поле `ownerId` равно `null`. У черновика `lessonId` равно `null`.

`revision` — целое. Сервер увеличивает его на каждый успешный `PUT`. Клиент хранит его рядом с документом и присылает ту ревизию, которую читал.

`camera` — сдвиг и масштаб мира доски. Координаты объектов — пиксели мира, не экрана.

Сервер не смотрит геометрию. На `PUT` он оставляет `id`, `kind`, `ownerId`, `lessonId`, `createdAt` как в базе и записывает `title`, `camera`, `objects`. В ответе `revision` на единицу больше, `updatedAt` — время сервера. После `200` локальную копию нужно заменить ответом: сервер мог дописать `ggbBase64` и свежий `src`.

Список досок приходит без `objects`:

```json
{
  "id": "6f1c2a40-7b1e-4d2a-9c33-0a1b2c3d4e5f",
  "title": "Урок дробей",
  "lessonId": 123,
  "kind": "student",
  "ownerId": 45,
  "updatedAt": "2026-09-28T00:40:12.000Z",
  "objectCount": 4
}
```

`objectCount` — длина `objects`. В списке ученика `class` нет: общая доска приходит только из открытия занятия.

## Объекты

Каждый элемент `objects` одной формы. Неизвестные ключи в `props` сервер сохраняет.

```json
{
  "id": "b7e1c2d0-1111-4222-8333-444455556666",
  "type": "sticky",
  "x": 120,
  "y": 80,
  "w": 200,
  "h": 160,
  "rotation": 0,
  "props": {}
}
```

`id` объекта — непустая строка. Координаты, размеры и `rotation` — конечные числа.

| `type` | Что лежит в `props` |
| --- | --- |
| `sticky` | `text`, `color` (`#fde68a` и другие), `fontSize` |
| `text` | `text`, `fontSize` |
| `shape` | `shape`: `rect` или `ellipse`, `fill`, `stroke` |
| `arrow` | `x1`, `y1`, `x2`, `y2` относительно рамки, `color`, `width` |
| `draw` | `points`: `[{ "x", "y" }]`, `color`, `width` |
| `image` | `fileId`, `src`, `name` |
| `geogebra` | `appName`: `geometry` или `graphing`, `ggbBase64`, `templateId` |

Лимит: до 200 объектов и до 8 МБ на документ. Иначе `PUT` отвечает `400`.

## Сохранение

IndexedDB пишется сразу. `PUT` — примерно раз в 700 мс тишины и при закрытии вкладки.

Тело `PUT` — тот же JSON, что вернул `GET`, с текущими `camera`, `objects`, `title` и `revision` последней успешной загрузки или сохранения.

```
PUT /student/boards/{id}
PUT /teacher/boards/{id}
Content-Type: application/json
Authorization: Bearer <token>
```

`200` — новый документ. Подставить его вместо локального, включая `revision`.

`409` — на сервере уже новее. Тело ответа — сам документ, без обёртки `detail`. Показать его и не сливать правки молча. Локальные штрихи этой ревизии на сервер больше не отправлять.

```json
{
  "id": "6f1c2a40-7b1e-4d2a-9c33-0a1b2c3d4e5f",
  "title": "Урок дробей",
  "lessonId": 123,
  "kind": "student",
  "ownerId": 45,
  "revision": 8,
  "createdAt": "2026-09-28T00:13:00.000Z",
  "updatedAt": "2026-09-28T00:41:00.000Z",
  "camera": { "x": 64, "y": 72, "zoom": 1 },
  "objects": []
}
```

Остальные ошибки — `{ "detail": "текст" }`.

Пока один клиент не сделал `GET`, он рисует свой черновик. Чтобы увидеть чужое сохранение, снова запросить доску. Сравнивать `updatedAt` или `revision` и качать полный документ, когда они изменились. Сокетов нет.

Кто куда пишет:

- Ученик: `PUT` своей `student` и своего `draft`. `PUT` в `class` — `403`, текст «Эту доску можно только читать».
- Учитель: `PUT` только в `class` своего занятия. `PUT` в тетрадь — `403`, текст «Тетрадь ученика учитель не перезаписывает».
- Чужое занятие и чужая тетрадь — `403`.

## Ученик

Роль в токене — `student`. Учительский токен на этих путях получает `403`.

### Список своих досок

```
GET /student/boards
```

Свои `draft` и `student`, без `objects`, новые сверху. Общей `class` в этом списке нет.

**Ответ 200:** массив мета-объектов. Если досок нет — `[]`.

### Черновик

```
POST /student/boards
Content-Type: application/json
```

```json
{ "title": "Черновик" }
```

**Ответ 200:** полный пустой документ, `kind` равен `"draft"`, `lessonId` равен `null`, `revision` равен `1`.

Пустое название или длиннее 255 символов — `400`.

### Открыть, сохранить, удалить

```
GET    /student/boards/{id}
PUT    /student/boards/{id}
DELETE /student/boards/{id}
```

`GET` отдаёт полный документ. Ученик может прочитать свою тетрадь, свой черновик и `class` своего занятия.

`DELETE` разрешён только для своего `draft`.

**Ответ 200:**

```json
{ "ok": true }
```

`class` и `student` так удалить нельзя: `403`, «Удалить можно только свой черновик». Вместе с черновиком удаляются его картинки в хранилище.

Неизвестный UUID — `404`, «Доска не найдена». Кривой UUID — `422`.

### Открыть доски занятия

```
GET /student/lessons/{lessonId}/board
```

`lessonId` — числовой id из календаря учителя (`POST /teacher/lessons`).

**Ответ 200:**

```json
{
  "class": { "id": "…", "kind": "class", "ownerId": null, "lessonId": 123, "revision": 1, "objects": [] },
  "mine": { "id": "…", "kind": "student", "ownerId": 45, "lessonId": 123, "revision": 1, "objects": [] }
}
```

Оба документа полные. Если строк ещё не было, сервер создаёт их и возвращает.

Чужого занятия нет в ответе: `403`. Занятия нет: `404`.

На групповом занятии `class` общий, `mine` — тетрадь этого ученика.

## Учитель

Роль `teacher` или `admin`.

### Открыть доски занятия

```
GET /teacher/lessons/{lessonId}/boards
```

Создаёт недостающие строки. Чужая или несуществующая занятие — `404`.

**Ответ 200:**

```json
{
  "class": {
    "id": "…",
    "title": "Урок дробей",
    "lessonId": 123,
    "kind": "class",
    "ownerId": null,
    "revision": 1,
    "createdAt": "2026-09-28T00:13:00.000Z",
    "updatedAt": "2026-09-28T00:13:00.000Z",
    "camera": { "x": 0, "y": 0, "zoom": 1 },
    "objects": []
  },
  "notebooks": [
    {
      "id": "…",
      "title": "Урок дробей",
      "lessonId": 123,
      "kind": "student",
      "ownerId": 45,
      "updatedAt": "2026-09-28T00:13:00.000Z",
      "objectCount": 0
    }
  ]
}
```

`class` — полный документ. `notebooks` — тетради без `objects`. Чтобы прочитать решение, отдельно:

```
GET /teacher/boards/{id}
```

Туда же:

```
PUT /teacher/boards/{id}
```

`PUT` принимается только для `class`. Черновик ученика учителю не отдаётся: у него нет занятия, ответ `403`.

Отдельного `GET /teacher/lessons/{lessonId}/boards/{boardId}` нет.

## Картинки

Файл в JSON доски не класть: ни base64, ни `data:`. Сначала загрузка, потом `fileId` в объекте.

```
POST /student/boards/images
POST /teacher/boards/images
Content-Type: multipart/form-data
```

Поле файла — `file`. Форматы: jpeg, png, webp. До 10 МБ. Тип определяется по содержимому, не по расширению.

**Ответ 200:**

```json
{
  "fileId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "name": "чертёж.png",
  "src": "https://…/boards/a1b2c3d4-e5f6-7890-abcd-ef1234567890.png"
}
```

`src` — публичный адрес, как у картинок заданий. `<img>` открывает его без заголовка `Authorization`. Подпись с `exp` не используется.

Дальше объект на доске:

```json
{
  "id": "img-1",
  "type": "image",
  "x": 40,
  "y": 40,
  "w": 320,
  "h": 240,
  "rotation": 0,
  "props": {
    "fileId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
    "name": "чертёж.png",
    "src": "https://…/boards/a1b2c3d4-e5f6-7890-abcd-ef1234567890.png"
  }
}
```

При каждом `GET` и успешном `PUT` сервер заново пишет `src` по `fileId`. В базе остаётся `fileId`. Если такого файла нет, `src` в ответе — пустая строка.

Удаление объекта с холста файл не стирает. Файл уходит, когда удаляют черновик или занятие, к которому картинка уже была привязана сохранением.

Чужой формат или файл больше 10 МБ — `400`.

## Шаблоны GeoGebra

Четыре id на клиенте (`right-triangle`, `circle`, `coordinates`, `parabola`) сервер сам не создаёт. Пока учитель не залил `.ggb` с таким `id`, в `props.ggbBase64` пусто и апплет не монтируется.

`ggbBase64` — файл `.ggb` в base64, тот самый параметр `ggbBase64` у `GGBApplet`. Свой JSON построения не подойдёт.

Пустая геометрия и пустые графики — не шаблоны. У них `templateId` равен `""`, `ggbBase64` начинает пустым и заполняется апплетом. Сервер такое поле не подменяет.

### Список

```
GET /board/geogebra-templates
```

Токен ученика или учителя.

**Ответ 200:** без base64.

```json
[
  {
    "id": "circle",
    "title": "Окружность",
    "appName": "geometry",
    "teacherId": 7
  }
]
```

Учитель видит свои строки. Ученик — шаблоны всех учителей, к которым привязан. `teacherId` нужен, потому что одинаковый `id` может быть у двух учителей.

Связь через `POST /admin/assign-student-to-teacher` оставляет ученику одного учителя: новый вызов заменяет предыдущего. Несколько учителей в списке появятся, только если в `teacher_students` реально несколько строк.

### Один шаблон

```
GET /board/geogebra-templates/{id}?lessonId=123
```

`lessonId` необязателен.

**Ответ 200:**

```json
{
  "id": "circle",
  "title": "Окружность",
  "appName": "geometry",
  "teacherId": 7,
  "ggbBase64": "UEsDBBQAAAAI…"
}
```

Если передан `lessonId`, берётся шаблон учителя этого занятия. Ученик должен быть участником занятия, иначе `403`. Без `lessonId` ученик получает любой совпавший шаблон своих учителей, стабильно — с меньшим `teacherId`. Учитель без `lessonId` получает свой шаблон.

Нет строки — `404`.

Клиент может сам положить `ggbBase64` в объект и потом сохранить доску. Если на `PUT` у объекта `type` равен `"geogebra"`, `templateId` непустой, а `ggbBase64` пустой, сервер подставляет построение сам:

- доска занятия — шаблон учителя этого урока;
- черновик — шаблон с меньшим `teacherId` среди учителей ученика.

Неизвестный `templateId` оставляет `ggbBase64` пустым. Уже заполненный `ggbBase64` сервер не затирает. Остальные ключи `props` (`custom` и другие) сохраняются.

### Учитель создаёт шаблон

```
POST /teacher/geogebra-templates
Content-Type: multipart/form-data
```

| Поле | |
| --- | --- |
| `file` | файл `.ggb`, до 8 МБ |
| `id` | `right-triangle`, `circle`, латиница, цифры, дефис и `_`, до 64 символов, с буквы или цифры |
| `title` | название, до 255 символов |
| `appName` | `geometry` или `graphing` |

**Ответ 200:** шаблон вместе с `ggbBase64`. Такой `id` у этого учителя уже есть — `409`, `{ "detail": "Шаблон с таким id уже есть" }`.

Замена:

```
PUT /teacher/geogebra-templates/{id}
Content-Type: multipart/form-data
```

Любое из полей `title`, `appName`, `file`. Хотя бы одно. Чужой или неизвестный id — `404`.

Удаление:

```
DELETE /teacher/geogebra-templates/{id}
```

**Ответ 200:** `{ "ok": true }`.

## Сценарий занятия

1. Учитель открывает урок: `GET /teacher/lessons/{lessonId}/boards`. Рисует `class`. Сохраняет `PUT /teacher/boards/{class.id}`.
2. Ученик открывает тот же урок: `GET /student/lessons/{lessonId}/board`. `class` показывает, пишет в `mine`.
3. Ответ `GET` сразу кладётся в IndexedDB. Штрихи пишутся туда же. Раз в ~700 мс и при `pagehide` уходит `PUT` с последней `revision`.
4. `200` — взять `revision` и документ из ответа. `409` — заменить холст телом ответа.
5. Учитель открывает тетрадь из `notebooks` через `GET /teacher/boards/{id}` и видит последний успешный `PUT`. Общий курсор не рисуется.
6. Картинку сначала `POST .../boards/images`, потом `fileId` и `src` в объект, потом `PUT` доски.
7. Шаблон: `GET /board/geogebra-templates/{id}?lessonId=...`, base64 в объект, потом `PUT`. Либо оставить `ggbBase64` пустым и положиться на подстановку сервера.
8. Кнопка «Новый урок» без календаря — `POST /student/boards`, это `draft`, не занятие.
